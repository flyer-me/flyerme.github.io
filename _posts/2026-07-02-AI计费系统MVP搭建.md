# 最小可行性系统落地步骤

## 1. 架构与前置准备

### 1.1 系统架构
```text
员工浏览器 → Open WebUI (:8080) → LiteLLM Proxy (:4000) → 各模型 API (OpenAI, Anthropic等)
                                      ↓
                               PostgreSQL（用户/项目/消费数据）
```

### 1.2 前置准备

**1. 安装 Docker 和 Docker Compose（Ubuntu 24.04 LTS）**

```bash
# 卸载旧版本（如有）
for pkg in docker.io docker-doc docker-compose-v2 podman-docker containerd runc; do
  sudo apt-get remove -y $pkg 2>/dev/null
done

# 添加 Docker 官方 GPG 密钥和仓库
sudo apt-get update
sudo apt-get install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 安装
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# 允许当前用户免 sudo 运行 docker
sudo usermod -aG docker $USER
newgrp docker

# 验证
docker --version
docker compose version
```

> 其他系统参考 [Docker 官方文档](https://docs.docker.com/engine/install/)。

**2. 准备 AI 模型供应商 API Key**

在对应平台注册并获取 API Key（示例）：
- OpenAI：访问 [platform.openai.com/api-keys](https://platform.openai.com/api-keys) → Create new secret key

记下获取的 Key，后续在步骤 3 的 LiteLLM 后台中配置。

**3. 开放防火墙端口**

```bash
# ufw 防火墙（Ubuntu 默认）
sudo ufw allow 8080/tcp comment 'Open WebUI'
sudo ufw allow 4000/tcp comment 'LiteLLM admin'
sudo ufw enable

# 云服务器额外在安全组中放行 8080、4000入方向
```

## 2. 核心组件部署 (Docker Compose)

在服务器上创建一个目录，新建 `docker-compose.yml` 和 `.env` 文件。

**docker-compose.yml**
```bash
# 生成 docker-compose.yml
cat > docker-compose.yml <<'YAMLEOF'
services:
  db:
    image: postgres:16.8-alpine
    restart: unless-stopped
    mem_limit: 512m
    cpus: 1
    environment:
      POSTGRES_DB: litellm
      POSTGRES_USER: litellm
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U litellm -d litellm"]
      interval: 5s
      retries: 10
    command: postgres -c shared_buffers=128MB -c max_connections=100

  litellm:
    image: ghcr.io/berriai/litellm-database:v1.89.1
    restart: unless-stopped
    depends_on:
      db:
        condition: service_healthy
    ports:
      - "4000:4000"
    environment:
      STORE_MODEL_IN_DB: "True"
      DATABASE_URL: "postgresql://litellm:${POSTGRES_PASSWORD}@db:5432/litellm"
      LITELLM_MASTER_KEY: ${LITELLM_MASTER_KEY}
      LITELLM_SALT_KEY: ${LITELLM_SALT_KEY}
    mem_limit: 2g
    cpus: 1
    command: --port 4000

  open-webui:
    image: ghcr.io/open-webui/open-webui:v0.8.2-slim
    restart: unless-stopped
    depends_on:
      - litellm
    ports:
      - "8080:8080"
    volumes:
      - owui_data:/app/backend/data
    mem_limit: 2g
    cpus: 2
    environment:
      OPENAI_API_BASE_URL: http://litellm:4000/v1
      OPENAI_API_KEY: ${OPEN_WEBUI_API_KEY}
      WEBUI_AUTH: "True"
      ENABLE_OLLAMA_API: "False"

volumes:
  pgdata:
  owui_data:
YAMLEOF
```

**.env**

在项目目录执行以下命令，一键生成 `.env` 文件：

```bash
MASTER_KEY="sk-$(openssl rand -hex 24)"
SALT_KEY="$(openssl rand -base64 32)"
PG_PASS="$(openssl rand -base64 24)"

cat > .env << ENVEOF
LITELLM_MASTER_KEY=$MASTER_KEY
LITELLM_SALT_KEY=$SALT_KEY
POSTGRES_PASSWORD=$PG_PASS
# 默认与 Master Key 相同，部署完成后在 LiteLLM 后台生成受限 Key 替换
OPEN_WEBUI_API_KEY=$MASTER_KEY
ENVEOF
```

执行完后查看并记录生成的值，后续步骤需要用到：

```bash
cat .env
```

> 重点记住 `LITELLM_MASTER_KEY` 的值，步骤 3 登录 LiteLLM 后台时需要用它作为密码。

> `.env` 中各变量说明：
> - `LITELLM_MASTER_KEY` — 自己生成的随机密码，用于管理员登录 LiteLLM 后台（用户名 `admin`），它不是任何 AI 供应商的 Key
> - `LITELLM_SALT_KEY` — 加密盐值，用于哈希存储内部 Key
> - `OPEN_WEBUI_API_KEY` — 前端调用模型的凭证，**默认沿用 Master Key 确保开箱即用**。部署完成后在 LiteLLM UI → API Keys 生成一个仅勾选模型调用权限的 Key，回来替换此行

**启动服务**

```bash
docker compose up -d
# 验证 LiteLLM 健康
curl http://localhost:4000/health/liveliness
```

> 部署完成后，建议尽快完成 [步骤 3](#3-平台初始化与模型接入-ai-采购与配置) 的供应商 Key 配置，并在 LiteLLM UI → API Keys 生成受限 Key 替换 `.env` 中 `OPEN_WEBUI_API_KEY` 的默认值，然后 `docker compose up -d --force-recreate open-webui` 使其生效。

## 3. 平台初始化与模型接入 (AI 采购与配置)

1. **登录管理后台**：访问 `http://localhost:4000/ui`，用户名输入 `admin`，密码输入 `.env` 中的 `LITELLM_MASTER_KEY`。
2. **配置供应商密钥**：在 UI 左侧导航进入 `API Keys`，添加企业采购的各厂商 API Key。
3. **添加可用模型**：进入 `Models`，点击 `+ Add Model`，配置模型映射（如将 `gpt-4o` 映射到真实模型）。后续调用时将按模型名称显示。

## 4. 用户与项目计费配置

为了实现按多维度核算，本节以按人、项目为例，需要创建用户、分配项目标签，并生成带有计费追踪的 API Key。

### 4.1 创建用户与项目标签 (Tag)

下方 curl 命令中的 `${LITELLM_MASTER_KEY}` 来自 `.env` 文件，执行前先导出：

```bash
export $(grep -v '^#' .env | xargs)
```

在 LiteLLM UI 中操作，或通过 API 执行：
```bash
# 创建用户张三和李四
curl -X POST 'http://localhost:4000/user/new' \
  -H "Authorization: Bearer ${LITELLM_MASTER_KEY}" \
  -H 'Content-Type: application/json' \
  -d '{"user_id": "zhangsan", "user_alias": "张三"}'

# 创建项目标签
curl -X POST 'http://localhost:4000/tag/new' \
  -H "Authorization: Bearer ${LITELLM_MASTER_KEY}" \
  -H 'Content-Type: application/json' \
  -d '{"tag_name": "project-alpha"}'
```

### 4.2 为员工生成专属计费 API Key
为员工生成专属密钥，绑定用户身份和项目，并可设置预算上限：
```bash
curl -X POST 'http://localhost:4000/key/generate' \
  -H "Authorization: Bearer ${LITELLM_MASTER_KEY}" \
  -H 'Content-Type: application/json' \
  -d '{
    "user_id": "zhangsan",
    "metadata": {"tags": ["project-alpha"]},
    "max_budget": 100.0,
    "models": ["gpt-4o", "claude-3-5-sonnet"]
  }'
```
> **效果**：该 API Key 消费数据同时归属个人和项目。

## 5. 员工使用指南 (Open WebUI 对接)

1. 员工访问 `http://<服务器IP>:8080`。
2. 首次访问点击“注册”，创建个人 Open WebUI 账号（管理员可在后台审批或配置允许注册）。
3. **配置专属计费密钥**：
   - 员工登录后，点击右上角头像 → `Settings` (设置) → `Connections` (连接)。
   - 在 OpenAI API 区域，确保 URL 为 LiteLLM 地址（由服务器默认下发）。
   - 填入管理员在步骤 4.2 中为其分配的**专属 API Key**，点击保存。
4. 回到主界面，在模型下拉框中选择对应的 AI 模型即可开始对话使用。

## 6. 验证与数据看板

**发送测试请求**

用步骤 4.2 为员工生成的 API Key 替换下方 `<员工Key>`，发送测试请求：

```bash
curl -X POST 'http://localhost:4000/v1/chat/completions' \
  -H 'Authorization: Bearer <员工Key>' \
  -H 'Content-Type: application/json' \
  -d '{"model":"gpt-4o","messages":[{"role":"user","content":"测试企业AI平台"}]}'
```

**查看计费与消费统计**
1. 管理员打开 `http://<服务器IP>:4000/ui` → `Spend & Usage`。
2. 按 **User** 筛选：查看各员工（张三、李四）的具体消费金额与 Token 用量。
3. 按 **Tag** 筛选：查看各业务线/项目的总体消费，便于财务进行内部成本分摊。
4. 可自行导出报表。

## 7. 版本升级

固定版本号后的安全升级步骤：

1. 查阅上游 Changelog（[LiteLLM Releases](https://github.com/BerriAI/litellm/releases)、[Open WebUI Releases](https://github.com/open-webui/open-webui/releases)），确认无 Breaking Changes
2. `docker compose down`（数据卷保留不删）
3. 修改 `docker-compose.yml` 中镜像版本号
4. `docker compose up -d`
5. `docker compose logs -f` 观察启动日志，确认无异常后完成

> 建议每次只升一个组件，间隔观察一天再升下一个。生产环境先在测试机验证。
